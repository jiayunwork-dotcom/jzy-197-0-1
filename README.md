# 选矿厂浮选回路数据校正后端

对浮选回路流程考查数据做**带物料/金属守恒约束的加权最小二乘校正（data reconciliation）**，
并提供可观测性判断、粗差识别、数据集版本管理、校正结果复用、版本对比和回收率走势。

技术栈：Python 3.12 + Flask + NumPy（不使用任何现成的数据校正/优化库），
持久化 PostgreSQL 16，Docker Compose 编排。模块划分：

| 模块 | 职责 |
|---|---|
| `app/topology.py` | 回路拓扑数据类、版本化、录入校验 |
| `app/measurement_model.py` | 测量值、相对标准差与默认值、变量/测量组装、权重 |
| `app/reconciliation.py` | 非线性守恒约束建模、逐次线性化（SQP/拉格朗日–牛顿）求解 |
| `app/observability.py` | 未测变量的唯一可观测性分析（约束雅可比列空间秩） |
| `app/gross_error.py` | 全局 χ² 检验、节点检验、测量检验（serial elimination 剔除重算） |
| `app/statsutil.py` | 正态/卡方分布 CDF 与分位数（不引第三方统计库） |
| `app/storage.py` | PostgreSQL 16 版本存储（拓扑版本、考查版本、校正结果绑定） |
| `app/api.py` | Flask 接口与 JSON 错误约定 |

> 目录内还有一个 `MemoryStore`（DSN=`memory://`）实现同一存储接口，
> 仅供无数据库环境下的测试和本地试跑，生产始终用 PostgreSQL。

## 1. 问题定义与数学模型

### 1.1 拓扑

- **节点（node）**：给矿点、粗选、精选、扫选、合流点等工艺单元。
  `source`（系统给矿边界）和 `sink`（系统产品/尾矿边界）是两个虚拟边界节点，
  不在拓扑里显式声明。
- **物流（stream）**：每股物流有 `source`/`target` 两个端点。端点为 `null` 表示
  挂在系统边界：`source=null` 为进系统（给矿），`target=null` 为出系统（精矿/尾矿等）。
- 关联矩阵 A（行=真实节点，列=物流）：物流进节点取 −1，出节点取 +1。
  边界物流只在其非空的一端出现。

### 1.2 变量与约束

每股物流 s 有干矿流量 F_s（t/h）以及考查声明的每种元素 e 的品位 G_{s,e}
（内部用小数，0–1；接口用百分数，0–100）。

对每个**真实节点** n：

- 干矿守恒：`Σ_s A[n,s]·F_s = 0`
- 元素 e 金属守恒：`Σ_s A[n,s]·F_s·G_{s,e} = 0`

边界节点（source/sink）不建约束——它们正是系统不平衡进出的开口。

### 1.3 目标函数（加权最小二乘）

只对**测量值**施加调整惩罚；未测变量是自由变量，其可观测性单独分析：

```
min  Σ_{测了的 F}  ((F  - F_meas)/σ_F )²
   + Σ_{测了的 G}  ((G  - G_meas)/σ_G )²
s.t. 上述全部守恒约束
```

标准差是绝对标准差：`σ = 相对标准差(rsd) × 测量值`。金属量 = 流量×品位，
金属守恒是非线性约束。

### 1.4 求解思路：逐次线性化（拉格朗日乘子法 + 牛顿步）及理由

约束对状态变量是双线性的、规模不大（一个回路几十股物流、几百个约束），
因此选用**逐次线性化 SQP/广义高斯消去**，而不是按节点分解，理由：

1. 双线性约束下，每一步的雅可比是解析的、构造廉价；
2. 一个测量可能同时关联多个节点（循环流、合流点），按节点分解需要反复协调，
   而全回路 KKT 系统一次解出，逻辑简单、残差可控；
3. KKT 系统天然包含未测变量（其权重为 0），不需要给未测量填“伪初值方差”；
4. 每一步都是线性等式约束二次规划，解唯一，便于做秩/可观测性分析。

迭代（x 为全部变量，σ 只在测量位对角非零）：

```
残差 h(x)；雅可比 H = ∂h/∂x
求解 KKT：
  [ W   Hᵀ ] [Δx]   [ -W(x − x_meas) ]
  [ H    0 ] [ λ ] = [  -h(x)         ]
x ← x + αΔx，α 由背驰（merit）函数线搜索选取（≤1，保证流量/品位不出域）
```

W = diag(1/σ²)（未测位为 0），x_meas 在未测位取当前迭代值（该项为 0）。
KKT 用 NumPy `lstsq` 求解，同时拿到数值秩；秩亏时给出结构/数值诊断。

**收敛判据**（两条同时满足）：

- 每个节点干矿/金属平衡残差相对值 `max|h| / Σ_out F`（金属行用
  `Σ_out F·G`）< `tol=1e-10`（严格于性质要求的 1e-9）；
- 加权解步长 `‖Δx/σ‖∞` < 1e-8（第一次迭代豁免，避免初值即满足时的误判）。

**迭代上限**：默认 50 次。达到上限未收敛时，结果如实返回
`status="not_converged"`，附当前节点残差表、残差相对最大值和已用迭代次数，
不伪装成功；残差合格但步长未静时返回 `status="converged"`。

### 1.5 可观测性

未测变量 x_u 只有在能被守恒约束唯一确定时才允许给数。线性化后约束的
雅可比 H（本问题结构在每处迭代点一致，金属行随点变化但秩性质稳定），
取未测变量对应列 H_U 做 SVD：

- `rank(H_U) = 未测变量数` → 全部可观测；
- 否则零空间中非零分量对应的未测流量（及未测品位）**不可观测**，
  校正被拒绝（HTTP 422），返回不可观测变量清单和零空间方向；
  调用方显式传 `accept_unobservable=true` 时才返回（不可观测量为 `null`）。

判据在初值点和收敛点各做一次，结论应一致（不一致时以收敛点为准并在报告注明）。

### 1.6 粗差识别

冗余度 `r = 测量数 − 未测变量数 = 测量数 − (总变量数 − 测量数)`，
等于约简约束协方差的秩；r≤0 时没有统计冗余，无法做粗差检验，
结果里 `gross_error.test_available=false`。

r>0 时对**守恒约束残差**做检验（测量误差按 σ 加权）：

- **全局检验**：χ²_r = hᵀ (H·diag(σ²)·Hᵢ)⁺ h，服从 χ²(r)。
  超过 χ²₀.₉₅(r) 判为“存在粗差”。
- **节点检验（约束检验）**：约简后各约束的标准化残差
  `v_i = h_red,i / sqrt(Σ_red,ii)`，绝对值超 z₀.₉₇₅≈1.96 标出嫌疑节点行。
- **测量检验（measurement test）**：调整量投影
  `a = Σ_meas·Hᵀ·Σ_h⁻¹·h`，`z_j = a_j / sqrt((Σ_meas − S)_{jj})`，
  超临界值的测量列入嫌疑清单，按 |z| 排序，给出测量编号、数值、σ、
  调整量和统计量。

被 `excluded_measurements` 剔除的测量既不进目标函数也不进冗余分析。
对嫌疑测量可在重算时把其测量编号加入剔除集合（serial elimination），
看全局检验是否恢复正常——由接口调用方决定剔除哪些，服务不自动删数。

### 1.7 测量默认相对标准差（可在请求里逐项覆盖）

未显式给 `rsd` 时按类别取默认值，定义在 `measurement_model.py`，数值为
行业常见皮带秤/化验精密度的经验起点，**投产前应按本厂重复取样、
平行化验的数据用实际标准差替换**：

| 类别 | 默认 rsd |
|---|---|
| 干矿流量（皮带秤，`flow_kind=belt`） | 1.5% |
| 干矿流量（其他/未注明：流量计折算、给矿估算等） | 3.0% |
| 品位 ≥10%（百分数） | 2.0% |
| 品位 1%–10% | 4.0% |
| 品位 <1% | 8.0% |

σ=rsd×测量值；品位按百分数测量值分档，内部换算成小数后 σ 同比缩放。
**rsd 必须 >0，流量必须 ≥0，品位必须在 [0,100]%，否则拒收。**

### 1.8 回收率

- 物流 s 的元素回收率（相对系统总给矿）：
  `100 · (方向·F_s·G_s,e) / Σ_边界给矿 F·G`，出系统方向取正。
- 精矿总回收率：所有标记 `role=concentrate` 的出系统物流金属量之和
  除以总给矿金属量；未标角色时用全部出系统物流。
- 趋势/对比接口按同一口径取每次考查**所选校正结果**里的值。

## 2. 版本与并发

- 回路（circuit）下拓扑按版本（topology_version，整数自增）保存；
  考查必须声明 `topology_version`。拓扑变更后新建版本，旧考查结果永远绑定旧拓扑。
- 考查数据（survey）下数据版本（survey_version）自增；化验补送/更正形成新版本，
  旧版本与旧校正结果保留。
- 校正结果绑定 `(survey_id, survey_version, topology_version, settings)`，
  settings 含剔除测量集合、求解参数、是否接受不可观测等；重复提交幂等返回已有结果。
- 修订考查走乐观锁：先 `GET` 拿到版本号/etag，提交修订带 `base_version`；
  两人先后改同一考查，后提交方收到 **409 Conflict**（PostgreSQL 用行锁/唯一约束，
  内存后端同样校验），不会静默覆盖。

## 3. 接口一览（详见 docs/API.md）

```
POST/GET  /api/circuits                         回路
GET/PUT   /api/circuits/<cid>/topology          录入/取最新拓扑（PUT 产生新版本）
GET       /api/circuits/<cid>/topology/<ver>
POST/GET  /api/surveys                          考查（声明 circuit 与 topology_version）
GET/PUT   /api/surveys/<sid>                    查询/修订（PUT 产生新版本，乐观锁）
GET       /api/surveys/<sid>/versions/<v>
POST      /api/reconciliations                  提交校正（幂等）
GET       /api/reconciliations/<run_id>         结果
GET       /api/reconciliations/<run_id>/balance-sheet
GET       /api/surveys/<sid>/compare?v1=&v2=    同考查两数据版本对比
GET       /api/surveys/<sid>/recovery-trend?months= 连续考查回收率走势
GET       /api/health
```

## 4. 本地运行

```bash
docker compose up --build            # app :8000, postgres :5432
# 或无数据库试跑（仅开发/测试）：

```
